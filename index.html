Memahami Konsep Vibe Coding

Vibe Coding adalah pendekatan pemrograman berbantuan kecerdasan buatan (AI) di mana pengembang berfokus pada niat, alur logika, dan hasil akhir menggunakan bahasa alami, sementara Large Language Model (LLM) bertugas menulis, memodifikasi, dan memperbaiki sintaks kode secara iteratif.

i Asal-Usul & Evolusi Istilah

Istilah "Vibe Coding" dipopulerkan oleh peneliti AI terkemuka Andrej Karpathy (mantan Direktur AI di Tesla dan salah satu pendiri OpenAI) pada Februari 2025. Ia menggambarkan cara baru membangun perangkat lunak di mana pengguna sepenuhnya menyerahkan penulisan baris demi baris kode kepada AI, cukup dengan memberikan instruksi dalam bahasa sehari-hari, menjalankan hasilnya, dan menyalin pesan galat (error) kembali ke AI jika terjadi masalah.

Pergeseran ini mengubah peran pembuat website dari sekadar penulis sintaks menjadi Arsitek Produk & Pengarah Sistem. Namun, para pakar rekayasa perangkat lunak seperti Simon Willison menekankan perbedaan penting antara vibe coding murni tanpa membaca kode (cocok untuk prototipe cepat) dengan AI-assisted engineering profesional (di mana kode tetap ditinjau, diuji, dan diamankan sebelum dipublikasikan).

Siklus Kerja Vibe Coding

Langkah 1
Prompt Spesifik

Jelaskan fitur, struktur data, dan batasan keamanan.

Langkah 2
Generasi Kode

AI menghasilkan HTML, CSS, JS, atau struktur full-stack.

Langkah 3
Uji & Observasi

Jalankan di browser/preview, uji semua tombol dan input.

Langkah 4
Iterasi & Audit

Perbaiki bug lewat prompt lanjutan dan audit keamanan.

Sangat Efektif Untuk:

  • Prototipe MVP (Minimum Viable Product) dalam hitungan jam.
  • Landing page, portofolio, kalkulator interaktif, dan micro-tools.
  • Eksplorasi desain UI/UX modern dengan Tailwind CSS.
  • Belajar arsitektur kode melalui contoh nyata yang langsung berjalan.

Berisiko Jika Tanpa Audit Pada:

  • Aplikasi yang menyimpan data sensitif pengguna atau transaksi keuangan.
  • Sistem autentikasi login, manajemen hak akses admin, dan pembayaran.
  • Integrasi API berbayar yang rawan kebocoran kunci rahasia (API Key).

Prinsip Security by Design

Mengapa Kode Vibe Coding Rawan Celah Keamanan?

Model AI dilatih dari jutaan repositori publik—termasuk kode tutorial yang mengabaikan keamanan demi kesederhanaan. AI mengutamakan agar kode "langsung berjalan tanpa error", bukan agar kode "tahan terhadap serangan siber".

Risiko #1: Kredensial Terekspos CWE-798

Hardcoded API Keys & Rahasia di Frontend

AI sering menaruh kunci API (Firebase, OpenAI, Supabase Service Key) langsung di file JavaScript browser sehingga siapa pun bisa mencurinya lewat fitur Inspect Element.

Mitigasi Wajib: Simpan kunci rahasia di file .env pada sisi server/backend, tambahkan .env ke dalam .gitignore, dan gunakan Backend Proxy atau aturan Row-Level Security (RLS).
Risiko #2: Injeksi Skrip Browser OWASP A03 / XSS

Cross-Site Scripting (XSS) via innerHTML

Untuk menampilkan input form atau data API dengan cepat, AI gemar memakai element.innerHTML = userInput. Penyerang dapat menyisipkan tag <script> berbahaya untuk mencuri sesi pengguna.

Mitigasi Wajib: Selalu gunakan element.textContent untuk teks biasa, atau bersihkan HTML menggunakan pustaka teruji seperti DOMPurify sebelum merender.
Risiko #3: Manipulasi Database OWASP A03 / SQLi

SQL Injection & Validasi Hanya di Klien

AI terkadang menggabungkan string query SQL secara langsung ("SELECT * FROM users WHERE id = " + id) atau hanya memasang validasi HTML required tanpa pengecekan di server.

Mitigasi Wajib: Gunakan Prepared Statements / Parameterized Queries pada setiap akses database dan selalu ulangi validasi tipe/panjang data di server.
Risiko #4: Kontrol Akses Lemah OWASP A01 / IDOR

Broken Access Control & CORS Terbuka Lebar

Endpoint API hasil AI sering mengatur Access-Control-Allow-Origin: * dan lupa mengecek apakah pengguna yang sedang login benar-benar pemilik data yang diminta.

Mitigasi Wajib: Terapkan prinsip Least Privilege, verifikasi kepemilikan sesi di setiap rute API, dan batasi domain CORS hanya ke domain produksi Anda.
Risiko #5: Supply Chain Slopsquatting

Halusinasi Paket & Dependensi Usang

AI bisa menyarankan pustaka npm/pip yang sudah tidak dipelihara (memiliki celah CVE) atau bahkan nama paket fiktif yang didaftarkan oleh peretas (package hallucination attack).

Mitigasi Wajib: Verifikasi eksistensi paket di registry resmi (npmjs.com / pypi.org) sebelum menginstal dan jalankan npm audit secara berkala.
Risiko #6: Konfigurasi Server OWASP A05

Ketiadaan HTTP Security Headers

Website statis maupun dinamis yang langsung di-deploy tanpa header keamanan rentan terhadap serangan Clickjacking (website disematkan di iframe palsu) dan MIME-sniffing.

Mitigasi Wajib: Tambahkan konfigurasi header X-Frame-Options: DENY, X-Content-Type-Options: nosniff, dan Content-Security-Policy pada vercel.json atau server.

Bagian A: 4 Pilar Prompt Berkualitas (Fungsional & Aman)

Sebelum menulis prompt, pastikan empat komponen berikut tercantum agar AI tidak menghasilkan kode setengah jadi atau rentan:

1. Peran & Konteks Stack

Tetapkan peran AI (Senior Developer & Security Engineer) dan teknologi spesifik yang dipakai.

2. Alur Input-Proses-Output

Rinci setiap fitur serta kondisi khusus seperti empty state dan pesan error ramah pengguna.

3. Batasan Keamanan Eksplisit

Wajibkan anti-XSS (textContent), validasi input berlapis, dan larangan hardcode API key.

4. Anti-Placeholder Rule

Larang AI menyingkat kode dengan komentar seperti // tulis logika di sini.
