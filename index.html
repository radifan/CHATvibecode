Memahami Konsep Vibe Coding

Vibe Coding adalah pendekatan pemrograman berbantuan kecerdasan buatan (AI) di mana pengembang berfokus pada niat, alur logika, dan hasil akhir menggunakan bahasa alami, sementara Large Language Model (LLM) bertugas menulis, memodifikasi, dan memperbaiki sintaks kode secara iteratif.

i Asal-Usul & Evolusi Istilah

Istilah "Vibe Coding" dipopulerkan oleh peneliti AI terkemuka Andrej Karpathy (mantan Direktur AI di Tesla dan salah satu pendiri OpenAI) pada Februari 2025. Ia menggambarkan cara baru membangun perangkat lunak di mana pengguna sepenuhnya menyerahkan penulisan baris demi baris kode kepada AI, cukup dengan memberikan instruksi dalam bahasa sehari-hari, menjalankan hasilnya, dan menyalin pesan galat (error) kembali ke AI jika terjadi masalah.

Pergeseran ini mengubah peran pembuat website dari sekadar penulis sintaks menjadi Arsitek Produk & Pengarah Sistem. Namun, para pakar rekayasa perangkat lunak seperti Simon Willison menekankan perbedaan penting antara vibe coding murni tanpa membaca kode (cocok untuk prototipe cepat) dengan AI-assisted engineering profesional (di mana kode tetap ditinjau, diuji, dan diamankan sebelum dipublikasikan).

Sangat Efektif Untuk:

  • Prototipe MVP (Minimum Viable Product) dalam hitungan jam.
  • Landing page, portofolio, kalkulator interaktif, dan micro-tools.
  • Eksplorasi desain UI/UX modern dengan Tailwind CSS.
  • Belajar arsitektur kode melalui contoh nyata yang langsung berjalan.

Berisiko Jika Tanpa Audit Pada:

  • Aplikasi yang menyimpan data sensitif pengguna atau transaksi keuangan.
  • Sistem autentikasi login, manajemen hak akses admin, dan pembayaran.
  • Integrasi API berbayar yang rawan kebocoran kunci rahasia (API Key).

Prinsip Security by Design

Mengapa Kode Vibe Coding Rawan Celah Keamanan?

Model AI dilatih dari jutaan repositori publik—termasuk kode tutorial yang mengabaikan keamanan demi kesederhanaan. AI mengutamakan agar kode "langsung berjalan tanpa error", bukan agar kode "tahan terhadap serangan siber".

Risiko #1: Kredensial Terekspos CWE-798

Hardcoded API Keys & Rahasia di Frontend

AI sering menaruh kunci API (Firebase, OpenAI, Supabase Service Key) langsung di file JavaScript browser sehingga siapa pun bisa mencurinya lewat fitur Inspect Element.

Mitigasi Wajib: Simpan kunci rahasia di file .env pada sisi server/backend, tambahkan .env ke dalam .gitignore, dan gunakan Backend Proxy atau aturan Row-Level Security (RLS).
Risiko #2: Injeksi Skrip Browser OWASP A03 / XSS

Cross-Site Scripting (XSS) via innerHTML

Untuk menampilkan input form atau data API dengan cepat, AI gemar memakai element.innerHTML = userInput. Penyerang dapat menyisipkan tag <script> berbahaya untuk mencuri sesi pengguna.

Mitigasi Wajib: Selalu gunakan element.textContent untuk teks biasa, atau bersihkan HTML menggunakan pustaka teruji seperti DOMPurify sebelum merender.
Risiko #3: Manipulasi Database OWASP A03 / SQLi

SQL Injection & Validasi Hanya di Klien

AI terkadang menggabungkan string query SQL secara langsung ("SELECT * FROM users WHERE id = " + id) atau hanya memasang validasi HTML required tanpa pengecekan di server.

Mitigasi Wajib: Gunakan Prepared Statements / Parameterized Queries pada setiap akses database dan selalu ulangi validasi tipe/panjang data di server.
Risiko #4: Kontrol Akses Lemah OWASP A01 / IDOR

Broken Access Control & CORS Terbuka Lebar

Endpoint API hasil AI sering mengatur Access-Control-Allow-Origin: * dan lupa mengecek apakah pengguna yang sedang login benar-benar pemilik data yang diminta.

Mitigasi Wajib: Terapkan prinsip Least Privilege, verifikasi kepemilikan sesi di setiap rute API, dan batasi domain CORS hanya ke domain produksi Anda.
Risiko #5: Supply Chain Slopsquatting

Halusinasi Paket & Dependensi Usang

AI bisa menyarankan pustaka npm/pip yang sudah tidak dipelihara (memiliki celah CVE) atau bahkan nama paket fiktif yang didaftarkan oleh peretas (package hallucination attack).

Mitigasi Wajib: Verifikasi eksistensi paket di registry resmi (npmjs.com / pypi.org) sebelum menginstal dan jalankan npm audit secara berkala.
Risiko #6: Konfigurasi Server OWASP A05

Ketiadaan HTTP Security Headers

Website statis maupun dinamis yang langsung di-deploy tanpa header keamanan rentan terhadap serangan Clickjacking (website disematkan di iframe palsu) dan MIME-sniffing.

Mitigasi Wajib: Tambahkan konfigurasi header X-Frame-Options: DENY, X-Content-Type-Options: nosniff, dan Content-Security-Policy pada vercel.json atau server.

Bagian A: Kriteria & Generator Template Prompt Modular

Susun instruksi yang jelas agar AI menghasilkan kode fungsional, aman dari celah siber, dan bebas dari potongan kode yang hilang.

1. Peran & Konteks Stack

Tetapkan peran AI (Senior Developer & Security Engineer) dan teknologi spesifik yang dipakai.

2. Alur Input-Proses-Output

Rinci setiap fitur serta kondisi khusus seperti empty state dan pesan error ramah pengguna.

3. Batasan Keamanan Eksplisit

Wajibkan anti-XSS (textContent), validasi berlapis, dan larangan hardcode API key.

4. Anti-Placeholder Rule

Larang AI menyingkat kode dengan komentar seperti // tulis logika di sini.

Matriks 10 Kriteria Fungsionalitas, Bisnis & Keamanan Web (C1–C10)

Gunakan tabel indikator berikut sebagai standar spesifikasi wajib dalam prompt agar website hasil AI siap rilis dan lolos uji kelayakan.

10 Parameter Audit
Kode Nama Kriteria Parameter / Indikator yang Diperiksa
C1 Navigasi & CTA Jumlah tautan navigasi utama (nav/header), tombol ajakan bertindak (CTA), ketiadaan broken link, serta fitur pencarian/filter.
C2 Responsivitas & Viewport Keberadaan konfigurasi tag <meta name="viewport"> untuk tampilan mobile.
C3 Informasi Profil / About Us Ketersediaan bagian atau halaman informasi profil usaha ("Tentang Kami" / "About Us").
C4 Kanal Komunikasi Umum Keberadaan informasi kontak umum seperti alamat, email, telepon, atau halaman "Hubungi Kami".
C5 Kontak Langsung Penjual Keberadaan dan validitas tautan kontak langsung ke penjual (seperti nomor tujuan WhatsApp yang aktif/valid dan tidak rusak).
C6 Alur Keranjang Belanja Ketersediaan fitur keranjang belanja / troli (add to cart).
C7 Mekanisme Pembayaran Ketersediaan alur atau informasi metode pembayaran (checkout, QRIS, transfer bank, e-wallet).
C8 HTTP Security Headers Kelengkapan 4 header keamanan HTTP: Content-Security-Policy (CSP), X-Frame-Options, X-Content-Type-Options, dan Strict-Transport-Security (HSTS).
C9 Performa & Pemuatan Status keterjangkauan halaman (reachable), ketiadaan error pemuatan, dan kelengkapan atribut src pada elemen gambar.
C10 Struktur Semantik DOM Validitas judul halaman (<title>), struktur halaman (termasuk deteksi client-side SPA), serta kebersihan HTML dari komentar sensitif atau informasi debug.

Fase 1: Persiapan & Pembuatan Kode dengan AI

Lokal · Persiapan
  1. Rakit Prompt & Generate Kode: Salin prompt dari Bagian A (yang sudah memuat indikator C1–C10) ke mesin AI pilihan Anda. Simpan kode yang dihasilkan ke folder khusus di komputer Anda (misalnya file utama index.html).
  2. Uji Fungsionalitas & Responsivitas di Browser: Klik ganda file index.html untuk membukanya di browser, tekan F12 → tab Console (pastikan nol error merah), lalu aktifkan ikon ponsel/tablet untuk memastikan tampilan responsif (Kriteria C2 & C9).
  3. Siapkan File vercel.json (Untuk Kriteria C8 Security Headers): Jika ingin menerapkan 4 header keamanan HTTP secara otomatis saat deploy ke Vercel, buat file bernama vercel.json di folder proyek Anda dengan isi berikut:
Contoh isi file vercel.json (Kriteria C8: 4 HTTP Security Headers) 
{
  "headers": [
    {
      "source": "/(.*)",
      "headers": [
        { "key": "X-Frame-Options", "value": "DENY" },
        { "key": "X-Content-Type-Options", "value": "nosniff" },
        { "key": "Strict-Transport-Security", "value": "max-age=63072000; includeSubDomains; preload" },
        { "key": "Content-Security-Policy", "value": "default-src 'self' https: 'unsafe-inline'; img-src 'self' https: data:;" }
      ]
    }
  ]
}

Fase 2: Membuat Akun & Repository di Laman GitHub

Laman GitHub.com · UI
  1. Buat Akun GitHub: Buka github.com, klik tombol Sign up di pojok kanan atas, masukkan email aktif, buat kata sandi kuat, tentukan username, dan selesaikan kode verifikasi yang dikirim ke email Anda.
  2. Aktifkan Wajib Two-Factor Authentication (2FA): Klik foto profil Anda di pojok kanan atas → pilih Settings → di menu kiri klik Password and authentication → klik tombol hijau Enable two-factor authentication dan pindai kode QR menggunakan aplikasi Authenticator di ponsel Anda.
  3. Buat Repository Baru via Tombol UI: Kembali ke halaman beranda GitHub, klik ikon + di bilah atas (sebelah ikon profil) → pilih New repository.
  4. Konfigurasi Pengaturan Repository:
    • Repository name: Ketik nama proyek tanpa spasi (contoh: katalog-kopi-nusantara).
    • Public / Private: Pilih lingkaran Public agar dapat langsung di-deploy gratis pada paket Hobby Vercel.
    • Initialize this repository with: Centang kotak Add a README file agar cabang utama (main) langsung terbentuk secara otomatis.
    • Klik tombol hijau Create repository di bagian bawah halaman.

Fase 3: Unggah File & Commit Pertama di Laman GitHub (Tanpa Terminal)

Laman GitHub.com · Drag & Drop
  1. Buka Menu Unggah File di Laman Repository: Pada halaman utama repository Anda (tab <> Code), klik tombol dropdown Add file (di sebelah kanan atas daftar file) → pilih Upload files.
  2. Seret & Lepas (Drag & Drop) File Website: Seret file index.html (serta vercel.json atau aset lainnya) dari folder komputer Anda ke area kotak "Drag files here to add them to your repository", atau klik tautan choose your files. (Pastikan Anda tidak ikut menyeret file .env yang berisi kunci rahasia!).
  3. Tulis Pesan Commit Pertama & Simpan ke Cabang main:
    • Gulir ke bagian bawah halaman pada kotak berjudul Commit changes.
    • Pada kolom baris pertama (ringkasan commit), ketik pesan yang jelas, misalnya: feat: unggah struktur awal website.
    • Pastikan opsi radio Commit directly to the main branch terpilih.
    • Klik tombol hijau Commit changes. Tunggu beberapa detik hingga Anda diarahkan kembali ke halaman utama repository dan melihat file index.html sudah terdaftar di cabang main.

Fase 4: Membuat Branch, Edit/Commit Perubahan & Pull Request di Laman GitHub

Quality Gate · UI Review

Saat Anda memperbarui kode hasil iterasi AI, gunakan fitur cabang (branch) dan Pull Request (PR) langsung di antarmuka web GitHub agar perubahan teraudit sebelum tayang ke publik:

  1. Buat Branch Fitur Baru Lewat Dropdown Cabang:
    • Di halaman utama repository, klik tombol dropdown cabang bertuliskan main (di sebelah kiri atas daftar file).
    • Ketik nama cabang baru di kolom pencarian dropdown, misalnya: fitur-update-ui.
    • Klik tulisan biru Create branch: fitur-update-ui from main yang muncul di bawahnya. Anda otomatis berpindah ke cabang baru tersebut.
  2. Perbarui File & Lakukan Commit pada Cabang Fitur:
    • Cara A (Edit Langsung di Web): Klik nama file (misal index.html) → klik ikon pensil (Edit this file) di pojok kanan atas kotak kode → tempelkan kode pembaruan dari AI → klik tombol hijau Commit changes... di kanan atas.
    • Cara B (Unggah File Pengganti): Klik Add file → Upload files (pastikan dropdown cabang di kiri atas menunjukkan fitur-update-ui), unggah file terbaru dengan nama yang sama untuk menimpanya, lalu klik Commit changes.
  3. Buka Pull Request (PR) di Laman GitHub:
    • Kembali ke tab <> Code. Anda akan melihat banner kuning bertuliskan "fitur-update-ui had recent pushes"; klik tombol hijau Compare & pull request (atau buka tab Pull requests → New pull request).
    • Pastikan panah penggabungan menunjukkan base: main ← compare: fitur-update-ui.
    • Isi judul dan deskripsi perubahan, lalu klik tombol hijau Create pull request.
  4. Audit Kode di Tab Files changed & Merge Pull Request:
    • Di halaman Pull Request, klik tab Files changed untuk memeriksa perbedaan baris hijau (ditambah) dan merah (dihapus). Pastikan tidak ada API key yang bocor, innerHTML berbahaya, atau komentar debug sensitif (Kriteria C10).
    • Kembali ke tab Conversation, gulir ke bawah, lalu klik tombol hijau Merge pull request → klik Confirm merge.
    • Setelah status berubah menjadi ungu (Merged), klik tombol Delete branch untuk membersihkan cabang sementara.

Fase 5: Publish ke Vercel & Continuous Deployment (Go Live)

Vercel.com · Publik HTTPS
  1. Buat Akun Hobby Gratis di Vercel: Kunjungi vercel.com, klik Sign Up, pilih paket Hobby (Gratis), lalu klik Continue with GitHub dan berikan izin akses ke akun GitHub Anda.
  2. Import Git Repository: Di dashboard Vercel, klik tombol Add New... → Project, cari nama repository Anda pada daftar Import Git Repository, lalu klik tombol Import.
  3. Atur Preset & Environment Variables:
    • Framework Preset: Pilih Other jika menggunakan HTML/CSS/JS statis, atau biarkan terdeteksi otomatis untuk Next.js/React/Vite.
    • Environment Variables: Jika aplikasi membutuhkan API key rahasia, buka bagian Environment Variables, masukkan pasangan KEY dan VALUE, lalu klik Add.
  4. Klik Deploy & Dapatkan URL Publik: Tekan tombol Deploy dan tunggu 30–60 detik. Setelah muncul layar perayaan, klik tombol Visit atau kartu pratinjau untuk membuka alamat publik ber-HTTPS Anda (contoh: https://nama-proyek.vercel.app).
  5. Otomatisasi Continuous Deployment & Preview URL: Setiap kali Anda menekan Merge pull request ke cabang main di laman GitHub, Vercel otomatis membangun ulang dan memperbarui website publik Anda. Selain itu, setiap Pull Request yang masih terbuka di GitHub otomatis mendapatkan Preview URL sementara dari Vercel untuk diuji secara online sebelum di-merge.
